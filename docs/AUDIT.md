# Аудит AutoUnpack: код и безопасность

Дата: 29.10.2026. Проверена версия, распространявшаяся скриптом `Установить.cmd`: программа ставилась в `%LOCALAPPDATA%`. Все найденные проблемы исправлены в версии 1.0.0 с установщиком.

## Модель угроз

Программа обрабатывает архивы, которые часто скачаны из интернета, то есть недоверенные данные. Злоумышленник контролирует содержимое архива, имя архива и соседние файлы в той же папке, например в распакованной ранее раздаче. Нельзя допустить запуска чужого кода, записи файлов за пределами целевой папки и снятия защитных меток Windows.

## Подробности

### 1. Внедрение команды PowerShell (высокий)

**Где.** В запасном способе для .zip вызывался `powershell -Command "Expand-Archive -LiteralPath '<путь>' ..."`. Апостроф `'` экранировался, но PowerShell считает кавычками и типографские символы `‘ ’ ‚ ‛`, а они допустимы в именах файлов.

**Чем опасно.** Архив с именем вида `x’; <команда>; ’.zip` при двойном клике выполнил бы произвольную команду. Путь срабатывал, если основной способ распаковки не справлялся с файлом, а повреждённый архив злоумышленник может сделать специально.

**Исправление.** Запасной путь через PowerShell удалён полностью. Для .zip его заменяют Проводник (основной способ) и `tar.exe`. Вызова интерпретатора команд с данными из имени файла в программе больше нет.

### 2. Подмена системных программ (высокий)

**Где.** `Process.Start("explorer.exe", …)` и `rundll32.exe` вызывались по короткому имени. При двойном клике рабочая папка программы совпадает с папкой архива. Windows ищет программу в том числе в текущей папке.

**Чем опасно.** Файл `explorer.exe` рядом с архивом, например в распакованной раздаче, запускался бы вместо Проводника после каждой распаковки.

**Исправление.** Все системные программы вызываются по полному пути: `System32\…` и `Windows\explorer.exe`. При запуске рабочая папка переключается на `System32`. У дочерних процессов рабочая папка тоже `System32`.

### 3. Потеря пометки «скачано из интернета» (средний)

**Где.** `tar.exe` не переносит поток `Zone.Identifier` с архива на извлечённые файлы.

**Чем опасно.** Программа из скачанного `.tar.gz` или `.7z` (в Windows 10) запускалась бы без предупреждения SmartScreen, а документы Office открывались бы без защищённого просмотра.

**Исправление.** После распаковки через `tar` пометка копируется на все файлы, ссылки при этом не обходятся. При распаковке Проводником пометку переносит сама Windows.

### 4. Канал связи с треем (средний)

**Где.** Именованный канал `AutoUnpack.Pipe` был общим для всех сеансов и пользователей, с правами доступа по умолчанию. Мьютекс при этом был отдельным для каждого сеанса.

**Последствия.** Если на компьютере работают два пользователя, трей второго не запускается нормально. Чужой процесс может заранее занять имя канала и получать пути к распакованным файлам.

**Исправление.**
- Имя канала включает SID пользователя и номер сеанса.
- Доступ на запись есть только у текущего пользователя.
- Перед отправкой клиент проверяет, что на другом конце процесс из того же `AutoUnpack.exe`.
- Число строк в одном сообщении ограничено.

### 5. Программа в папке, доступной на запись (средний)

**Где.** Раньше программа лежала в `%LOCALAPPDATA%\AutoUnpack` и запускалась при входе в Windows.

**Чем опасно.** Любой процесс пользователя мог подменить exe и закрепиться в автозапуске.

**Исправление.** Программа ставится в `Program Files`, куда без прав администратора писать нельзя. Остатки старой версии установщик удаляет.

### 6. Чтение пути к значку с правами администратора (средний)

**Где.** Путь к системному значку брался из `HKCR\CompressedFolder`. Эта ветка объединяет `HKLM` и `HKCU`, поэтому значение мог подложить пользователь.

**Исправление.** Путь читается только из `HKLM`. DLL загружается исключительно как ресурсы, без выполнения кода (`LOAD_LIBRARY_AS_DATAFILE | AS_IMAGE_RESOURCE`). Размеры ресурсов проверяются (п. 9).

### 7. Открытие пути из сообщения (низкий)

По клику на уведомление открывался путь, пришедший по каналу. Теперь открываются только существующие папки и только через `explorer.exe` по полному пути.

### 8. Символические ссылки при «распрямлении» (низкий)

Если единственный элемент архива — ссылка или точка соединения с тем же именем, её больше не «распрямляют». При переносе пометки (п. 3) в ссылки программа тоже не заходит.

### 9. Разбор ресурсов значка (низкий)

Добавлены проверки количества записей, длины группы и размера каждого ресурса.

### 10. Zip-бомбы (принято)

Архив размером в килобайты может распаковаться в сотни гигабайт. Программа не ограничивает распакованный размер, так же как Проводник и «Извлечь всё». При нехватке места окно копирования Windows сообщает об ошибке, и её можно отменить. Риск — заполнение диска, а не выполнение кода, поэтому он принят.

### 11. Цифровая подпись (рекомендация)

Без подписи Windows SmartScreen предупреждает при запуске установщика, а пользователь не может проверить, что файл не подменён. Пока что релизы публикуются вместе с контрольными суммами SHA-256 (`SHA256SUMS.txt`), а сборка идёт открыто в GitHub Actions. Для широкого распространения стоит получить сертификат подписи кода, например бесплатный для открытых проектов через SignPath Foundation.

### 12. Имитация Alt (инфо)

Если Windows не пускает окно Проводника на передний план, программа последним средством имитирует короткое нажатие Alt. На практике до этого почти не доходит: процесс, запущенный двойным кликом, сам передаёт Проводнику право выйти вперёд.

## Что проверено и в порядке

- **Выход за пределы папки** (`../`, абсолютные пути, «Zip Slip»). Проводник и `tar.exe` по умолчанию отвергают такие пути. `tar` также не пишет через символические ссылки.
- **Командная строка `tar`.** Пути заключены в кавычки, а символ `"` в именах файлов Windows недопустим.
- **Процессы.** Все дочерние процессы запускаются по полному пути, без оболочки (`UseShellExecute = false`). Исключение — системный просмотр архива по Shift: там используется `ShellExecuteEx` с явно указанным системным типом файла.
- **Привилегии.** Программа работает с правами пользователя. Права администратора нужны только установщику, и единственная операция под ними — вшивание значка в exe.
- **Сеть.** Программа не обращается к сети и не собирает данных.
- **Реестр.** Пользовательские настройки хранятся в `HKCU\Software\AutoUnpack`. При удалении программы удаляются все созданные ключи.

## Известные ограничения (не уязвимости)

- Пути длиннее 260 символов могут не обрабатываться, если в Windows не включена поддержка длинных путей.
- Архивы с паролем через Проводник запросят пароль. Через `tar` такая распаковка завершится ошибкой.
- Назначить программу по умолчанию автоматически нельзя, это ограничение Windows. Пользователь делает это один раз вручную.
